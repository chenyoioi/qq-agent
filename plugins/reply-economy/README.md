# 闲聊减负（reply-economy）

一眼能看出是日常闲聊的消息（短句、没图、没求助词），机器人回复时自动走「轻量模式」，
给整个软件减负。类型：**确定性型插件**（`plugins/`，靠 hooks + `llm.request-params` 工作）。

## 减了哪三处"运转"

| 减什么 | 怎么减 |
|---|---|
| 思考 token | 闲聊轮显式下发"关闭思考"（按宿主方言表 GLM/DeepSeek/Qwen 自动适配；拿不到方言表时静默跳过） |
| 工具往返轮次 | 把 web / knowledge / media 三类**重工具**从本轮工具列表里裁掉——模型看不见就不会调，一次工具调用 = 一次完整的模型往返 |
| 输出长度 | `max_tokens` 压到设置值（默认 600）。只在"思考确认已关"时才压——思考还开着的请求里思考 token 也计入 max_tokens，压了会把正文预算掐死 |

另在本次输入末尾追加一行轻量化引导（可关）。`send_message`、`send_sticker`、
`finish`、翻聊天记录、记忆这些轻工具**全部保留**——闲聊照样能说话、能发表情包。

## 判定规则（保守：宁可漏省不误伤）

触发批里**任何一条**满足下面任一条件，就按原来的全功率跑，不减负：

- 带 图片/视频/文件 附件
- 单条文字超过 30 字（可调）
- 命中复杂词表（为什么/怎么/帮我/搜/图/价格/天气……默认 40+ 个，可自己增删）
- 本轮是"主动开口"（活跃模式抛话题，需要发挥）

## 与现成插件的关系

- **通用思考控制（thinking-toggle-pro，smart 档）**：它也按复杂度开关思考。转换链
  按目录字母序执行，本插件排在它**前面**——若它把同一条消息判成"要开思考"，
  以它的结论为准（用户显式选的模式赢）。本插件独有价值在**裁工具 + 限输出**，
  这两件事没有任何现成插件做。
- **思考额度限制（thinking-budget）**：它管"思考烧太多就熔断"，排在更后面；
  它的「总输出上限」若设了值会覆盖本插件的上限（默认 0 = 不干预，不冲突）。
- **token 直接减半（early-finish）**：它省"发完话还要再调一轮 finish"的浪费，
  与本插件互补，建议都开。

## 看效果

- 会话页每次运行的用量里有附加统计 **replyEconomy**：这轮减负生效了几次请求。
- 控制台日志：「闲聊减负：本轮判为闲聊（短句闲聊）→ 关思考 / 裁重工具 / 输出上限 600」。

## 已知边界

- 判定是**机械规则**，不是语义理解："帮我看看"会因"帮"字全功率跑，
  "这瓜保熟吗"会当闲聊减负——方向是保守的：拿不准就全功率，最多少省点。
- 若闲聊判定里出现该搜没搜、答非所问，把那个关键词加进「复杂信号词」设置即可。
