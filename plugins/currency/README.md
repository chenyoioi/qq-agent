# 货币系统 · currency

让每个群拥有自己的金币钱包。**每个群独立账户**，默认货币名为“金币”，支持查询余额、转账、查看收支记录和财富排行。

同时为签到奖励、道具商店和小游戏提供统一的货币接口。其他插件或技能可以通过 **`currency.v1`** 接入，共用账户、处理支付与退款。

本扩展只提供基础账户与交易机制。签到、聊天奖励、任务、道具、商店、游戏和好感度兑换由业务扩展决定，不会自动因发言或好感度增发货币，也不需要额外模型或 API Key。

## 安装与配置

导入 `currency-1.0.1.zip`，或复制整个目录到宿主的 `plugins/currency/`。启用后在「插件 → 货币系统」配置：

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 货币名称 | 金币 | 仅改变显示名称，不重置余额或改变单位 |
| 主人 QQ 号 | 留空 | 多个用逗号分隔；主人可以调账和释放遗留预扣款 |
| 允许群友转账 | 开启 | 控制内置转账工具，不影响其他扩展的独立授权 |
| 扩展接入权限 | `{}` | 查询可用，第三方写操作需显式授权 |

接入权限示例：

```json
{
  "quest-reward": ["credit"],
  "item-shop": ["reserve", "capture", "release", "refund"],
  "gift-game": ["transfer"]
}
```

所有设置下一次调用生效。主人是本扩展明确配置的 QQ 号，昵称、群管理员身份、好感度均不会授予调账权限。新账户初始余额为 0；查询不存在的账户返回 0，不写文件。可由主人先发放测试金币，也可通过奖励扩展发放。

## 群聊使用

- “我还有多少金币？”——查询余额、冻结和可用金额。
- “把 20 金币转给 QQ 10002。”——从真实发言者钱包扣除，同时记入收款账户。
- “看看我的收支记录。”“金币排行榜。”
- 主人：“给 QQ 10001 发放 100 金币，作为活动奖励。”
- “查一下我的未结订单。”；主人核实订单停止交付后，可要求释放指定预扣款。

工具为 `currency__balance`、`history`、`rank`、`transfer`、`admin_adjust`、`holds`、`admin_release`。结果返回主会话，由主模型通过 `send_message` 按人设回复，工具自身不发送消息。模型结束、轮数耗尽时仍可能没有文字回复，插件不转发模型正文。

转账与管理操作必须关联本轮真实消息。程序验证来源 QQ、消息编号、时间、权限与去重；不从昵称或历史转述推断操作人。混有不同发言者的触发批拒绝修改，需操作人单独重新请求。自然语言是否明确授权、目标与金额的语义仍依赖主模型判断；没有消息编号、参数缺失或会话结束时拒绝执行。

## 开发者接入

[开发接口文档](API.md)包含权限配置、全部方法、错误码、重复请求处理和订单恢复流程。另附 [TypeScript 类型](api.d.ts)、[奖励示例](examples/reward.js)与[商店示例](examples/shop.js)。示例不会自动执行。

其他扩展在自己的工具或业务任务中取得接口：

```js
const money = api.capability('currency.v1', { consumer: 'my-plugin' });
if (!money) return; // 未安装、未启用或配置有误
const result = await money.balance({ scope: ctx.chatKey, userId: '10001' });
```

发放、支付等写操作需由安装者在设置中授予权限；接口版本和账户数据格式保持兼容。

## 数据保存与维护

- 账户和交易记录保存在宿主数据目录的 `currency.json`，支持独立实例的数据目录。停用插件后可以备份该文件。
- 保存失败时本次操作不生效；重试相同请求不会重复发币或扣款，重启后也保留交易记录。
- 预扣金额会暂时冻结，订单完成后结算、取消后释放。未结订单不会自动退款，由接入扩展负责恢复或经主人核实后处理。
- 数据损坏时停止写入，保留原文件。`currency.json.lock` 与对应 `.lock.owner-<PID>-<UUID>` 归属文件会在正常停用或进程退出时清理；强制结束后的遗留锁在下次启用时确认原进程已退出后自动回收，兼容旧版 PID 锁。活进程或归属无法确认的锁仍会阻止启动；多个实例同时启动时可能相互退让，可稍后重试。
- 数据目录需位于本机支持同目录硬链接的文件系统（如 Windows NTFS）。仍提示锁冲突时，先确认所有使用该目录的实例已退出，再排查锁与归属文件；不要删除 `currency.json`。
- 停用时若暂时无法删除自己的锁，会保留待清理记录，在重新启用（含热重载）、再次释放或进程退出时重试；清理完成前不恢复写入，也不会删除其他实例的锁。
- 修改货币名称不会改变余额。配置填错时会显示原因，保存正确配置后即可恢复；修改 `lib/` 代码后应重启宿主。

## 开发验证

```text
npm test -- currency
npm run pack:extension -- currency
```

测试验证余额不透支、原子转账、重试/重启去重、冻结结算互斥、全额退款一次性、权限和会话来源、磁盘失败、损坏数据、独占锁、多实例目录，以及外部奖励/商店示例。无第三方 npm 依赖。另有可选的真实宿主加载检查，运行方法见开发接口文档。所有检查均不代替真实 QQ 消息的自然语言联调。
